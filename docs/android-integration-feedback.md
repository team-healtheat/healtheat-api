# Android 연동: 인증, 계정 전환, 식사 기록

이 문서는 변경 브랜치의 계약이다. 배포 후 Swagger와 Android 실기기에서 다시 확인한다.

## 인증과 계정 전환

- 로그인은 `access_token`(30분, HttpOnly)과 `refresh_token`(마지막 갱신 후 30일, HttpOnly)을 발급한다. 두 쿠키를 클라이언트 쿠키 저장소에서 보관하고 모든 요청에 해당 경로의 쿠키를 자동 전송한다.
- 인증 API의 `GET /api/auth/csrf` 응답 토큰을 변경 요청의 `X-XSRF-TOKEN`에 담는다. 로그인·갱신 이후 CSRF 토큰을 다시 조회한다.
- 보호 API에서 401을 받으면 갱신 요청을 한 번에 하나만 보내고, 성공하면 원래 요청을 한 번만 재시도한다. `POST /api/auth/refresh`에도 CSRF가 필요하다. 갱신 토큰은 매번 교체되므로 이전 토큰의 동시 사용은 실패한다.
- 갱신도 401이면 인증 상태를 초기화하고 로그인 화면으로 이동한다. 로그아웃은 `POST /api/auth/logout`으로 서버 갱신 토큰을 폐기하고 쿠키를 만료한다.
- 로그인·로그아웃·인증 만료·계정 변경 시 이전 사용자의 화면 상태, 캐시, 채팅 메시지, sessionId를 모두 비운다. 새 사용자 정보 확인 후 `POST /api/chat/sessions`로 해당 사용자의 세션을 받아 복원한다. 404/410 세션은 버리고 새 세션을 만든다. 다른 사용자의 메시지나 세션을 화면에 남기지 않는다.
- 프론트 저장소의 상태 초기화와 401 재시도, Android WebView/HTTP 쿠키 처리는 프론트에서 별도로 구현하고 실기기 검증해야 한다.

## 사용자 및 식사 기록

- 회원가입의 선택 필드 `nickname`을 전달한다. 기존 계정은 `PATCH /api/users/me/nickname`으로 변경한다.
- `DELETE /api/users/me`는 JSON `password`를 요구하고 사용자 개인 데이터와 갱신 세션을 삭제한다. 성공하면 클라이언트 상태를 모두 지운다. 탈퇴 확인 화면은 프론트에서 구현한다.
- `PUT /api/meal-records/{id}`에 `sourceType`과 `items`를 전달해 기록된 날짜·끼니의 음식을 교체한다. 수정된 기록은 직접 입력 기록으로 처리한다. 기존 날짜와 끼니는 바꾸지 않는다.
- 건강 요인 응답의 `type`은 연동을 위한 코드이고 화면에는 `typeLabel`을 사용한다. 기존에 영어 이름으로 저장된 항목은 자동 번역되지 않는다.
- 실제 OpenAI 호출, 한국어 결과, 식단 다양성, 식사 기록 반영과 함께 서버와 Android를 이용한 통합 테스트가 필요하다.
